# Joker — онлайн-инфраструктура (Supabase + GitHub + Яндекс Игры)

## Файлы
- `index.html` — вся игра (единственный HTML-файл; раньше в репозитории лежала
  ещё и его точная копия `joker-game-v5.html` — удалена как дубликат, ничего
  на неё не ссылалось).
- `supabase_schema.sql` — **вся** база данных и **все** rpc-функции одним
  файлом: профили, монеты, скины, лиги, джекпот, столы, матчмейкинг, история.
  Раньше часть функций (профиль, матчмейкинг) лежала в отдельных
  `patch-*.sql`-файлах, которые нужно было не забыть выполнить отдельно —
  это и было частой причиной "онлайн не работает, играю только с ботами":
  без них клиент получает ошибку от Supabase и молча уходит в локальный
  режим с ботами. Теперь это один файл — выполнить полностью и только его.
- `yandex-sdk.js` — обёртка над Yandex Games SDK (игрок, реклама, лидерборды, покупки).
- `supabase-client.js` — обёртка над Supabase (профиль, монеты, скины, столы, реалтайм).
- `.github/workflows/build-yandex-zip.yml` — при пуше в `main` сам собирает зип для загрузки в кабинет разработчика. (Раньше папка называлась `.githut` — опечатка, из-за которой GitHub Actions вообще не видел workflow и он никогда не запускался.)

## Шаги настройки

### 1. Supabase
1. Зайти на supabase.com → New project.
2. Project Settings → API — скопировать `Project URL` и `anon public` ключ.
3. SQL Editor → вставить **всё содержимое** `supabase_schema.sql` целиком → Run. Если позже переустанавливаете схему после наших правок поверх старого проекта — просто выполните файл ещё раз, все функции объявлены через `create or replace function`, это безопасно повторять.
4. Вписать URL и ключ в `supabase-client.js` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`).
5. Проверка, что всё встало: SQL Editor → `select proname from pg_proc where proname like 'fn_%' order by 1;` — в списке должны быть в т.ч. `fn_ensure_profile`, `fn_join_or_create_table`, `fn_finalize_table_search`, `fn_leave_search_and_refund`. Если их нет — RPC-вызовы будут падать с ошибкой "could not find the function", и игра автоматически (но теперь уже видимым алертом, а не молча) уходит в офлайн-режим с ботами.

Важно: `service_role` ключ **никогда** не класть в клиентский код — только `anon`. Все изменения баланса/скинов идут через `rpc`-функции в схеме, они уже настроены как `security definer` и сами проверяют условия.

### 2. GitHub
1. Создать репозиторий, залить в него игру + эти файлы.
2. Workflow из `.github/workflows/` заработает сам при пуше в `main` — во вкладке Actions появится собранный `yandex-build.zip`.
3. Поправить путь `dist` в workflow на реальную папку с игрой, если сборки как таковой нет.

### 3. Яндекс Игры
1. Разработчикам Яндекс Игр → создать черновик игры.
2. В `index.html` подключить `<script src="https://yandex.ru/games/sdk/v2"></script>` перед своим кодом.
3. Вызвать `initYandexSDK()` при старте и `markGameReady()`, когда экран выбора формата уже показан.
4. В настройках игры (раздел про сеть/хосты) добавить домен твоего Supabase-проекта (`*.supabase.co`) в список разрешённых — иначе запросы к базе будут заблокированы.
5. Загрузить `yandex-build.zip` из GitHub Actions в кабинет разработчика.
